## 二、[P2，N13 残留] 质量归一化已接入，但残差和 Jacobian 仍未经行缩放进入求解器

**位置：**

`Geometry/Intersection/BlendJointLift.cs`  
`Geometry/Intersection/JointBlendResidual.cs`

### 已修好的部分

新增分母后：

\[
\max_i\frac{|F_i|}{d_i}\le10^{-12}
\]

替代了直接比较 raw `MaxAbs(F)`。原来 \(r=2^{-24}\)、径向距离误差达到 100% 却提前成功的输入，现在不会通过初始检查。这个改动是有效的。

### 还缺什么

当前通过停止检查后，仍然执行：

```csharp
TrySchurOrFullStep(j, f, ...)
```

传入的是原始 `j`、原始 `f`。新增加的 `denominators` 没有用于缩放它们。Schur 内块、完整 LU 和预测下降计算也仍基于未缩放系统。

所以准确状态应是：

> **无量纲接受判据已实现；用于求步和数值秩判断的行缩放尚未实现。**

不能将前者等同于规格要求的 frozen row scaling。

### 一个确定的线性化反例

采用当前 Joint 支持的圆 spine 制造例：

\[
A(c)=c_z,\qquad D(c)=\|c\|^2-R^2,\qquad S(x)=x_z,\qquad p(x)=x_y.
\]

设置：

\[
R=\lambda,\qquad r=\lambda/4,\qquad
c=(R,0,0),\qquad x=(R+2r,0,0).
\]

这是同一几何构造的等比例缩放。三种尺度下，新增的归一化残差最大值都为 **0.5**，都应该进入求步。

我按当前 `AssembleJacobian` 和 `LuFactorize` 的运算顺序与枢轴门槛复算：

| 几何尺度 \(\lambda\) | 当前 Schur 内块 LU | 当前完整 6×6 LU | 对同一系统正确施加新行权重后 |
|---:|---|---|---|
| \(1\) | 成功 | 成功 | 成功 |
| \(2^{-54}\) | **`Singular`** | **`Singular`** | 成功 |
| \(2^{54}\) | **`Singular`** | **`Singular`** | 成功 |

正确行缩放后的三个矩阵，二范数条件数均约为 **4.27**。这说明被拒绝的并不是几何约束真的失去独立性，而是 raw 行量级触发了当前全矩阵相对枢轴门槛。枢轴检查确实使用 `n * epsilon * maxAbs(matrix)`。

这是**初始线性化和求步入口的独立复算**，不是完整 C# 非线性迭代实测，也不是要求公开模型接口支持任意物理分辨率。

### 修复建议

每次接受态确定行权重 \(W\)，然后同步执行：

\[
f_s=Wf,\qquad J_s=WJ.
\]

Schur 提取、完整求解和预测下降都使用相容的缩放系统。存在 trial 接受／拒绝比较时，同一次比较必须冻结相同的 W。

继续保留独立几何验收；不要因为归一化范数小就忽略半径、spine 分支和允许圆弧。已有小半径回归应保留，再加入尺度变化及等价方程缩放的控制测试。

## 三、[P2，N9 新边界问题] Spun 的公式已正确，但“是否在轴上”取决于轴参考点选在哪里

**位置：**

`Geometry/Evaluation/SweptSpunImplicit.cs` → `SpunConstraints`、`TryRecoverSpunAngle`

双约束及其导数已经按规格正确实现：

\[
h_1=\hat A\cdot(x-P)-\hat A\cdot(C-P),
\]

\[
h_2=\|P_\perp(x-P)\|^2-\|P_\perp(C-P)\|^2.
\]

原来“零集合是径向正交、梯度又差负号”的问题可以关闭。

但新增轴退化检查使用：

```csharp
scaleX = 1.0 + |x - P|;
radialSquared <= 1e-24 * scaleX * scaleX
```

其中包含沿轴方向的距离。**将 P 沿同一条轴移动，不改变旋转轴，却能改变函数的成功／失败状态。**

### 精确反例

取：

```text
axis              = (0, 0, 1)
profilePoint      = (1, 0, 1e13)
profileDerivative = (0, 0, 1)
point             = (0, 1, 1e13)
```

这是半径 1 的正则圆柱上的旋转点，旋转角为 \(\pi/2\)。

比较两个表示**同一条轴线**的轴点：

| 轴点 P | 径向距离平方 | 当前退化阈值 | 当前结果 |
|---|---:|---:|---|
| `(0,0,0)` | 1 | 约 100 | **`Singular`** |
| `(0,0,1e13)` | 1 | 约 `4e-24` | `Success` |

两个约束的正确残差在两种表示下都为零。`TryRecoverSpunAngle` 也有相同问题：第一种表示返回 false，第二种可以恢复 \(\pi/2\)。本轮已按源码公式复算。

### 修复建议

轴退化应依据径向几何、请求分辨率及投影计算误差判断，不能直接用任意轴向偏移扩大阈值。

建议将退化策略改为对**轴参考点沿轴平移不变**的局部判据；需要考虑大坐标误差时，应估计具体投影运算的误差，而不是把完整的 \(\|x-P\|\) 当作几何退化尺度。

回归应保留当前倾斜轴、旋转点和导数测试，再加上述“同轴不同参考点”测试。这是正则输入被误拒，按 P2 处理，不是新的错误分支成功。

当前 Terminator 成功后固定存入：

```csharp
terminatorQuality = 1e-7 * Math.Max(anchor.ChordLength, 1.0);
```

再次查询却仍然使用：

因此，第一次即使求到非常准确的点，**第二次同参数、同阶数、同规则查询仍必然拒绝这个缓存样本**。这由当前判断关系直接确定。

这里对应显式规则的内部 Terminator 缓存入口，公开 GATE-T 状态不变。不能因为公开门禁未关闭，就把内部已实现的缓存回归算作不存在。

### 修复建议

让求解接受要求、样本质量记录和本次复用请求采用同一套契约。

可以选择记录实际验证得到的更紧误差估计，也可以明确区分不同 QueryKind 的请求精度。**不能简单把所有命中阈值放宽到 `1e-7`，使原本要求更严格的请求也被悄悄满足。**

### 3. 冷热报告的 `Residual` 仍然混入了质量值

新字段注释把 `Residual` 定义为“raw equation units”，但 L2/L3 精确命中时仍然把：

```csharp

```

填进 `Residual`，同时也填进 `QualityError`。于是冷调用报告的是 raw 方程残差，热调用同一字段却变成长度质量值。

修复时应单独保存可复用的 residual summary，或者明确报告“缓存命中，未重新计算 raw residual”。不要用质量值替代另一个量纲的诊断字段。

### 4. “认证的误差上界”这个命名也应收窄

当前代码直接将发布门的配置容差赋给 `QualityError`；发布门检查的主要是曲面偏差、参数平面残差和 Newton 修正量代理。它没有构造严格误差包围，因此不能据此称为 **certified position-error bound**。

可以记录“已通过的数值验证容差”或“数值误差估计”，并保留相应质量等级；不要把配置阈值自动升级为数学认证。这个术语修正不要求现在引入完整区间求根，但需要与规格的 `NumericallyVerified`／`CertifiedLocalRoot` 区分一致。
