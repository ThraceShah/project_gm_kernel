## 1. [P1，内部 Terminator] “足够贴近曲面”仍被当成“目标位置足够准确”

**位置：**

`Geometry/Intersection/TerminatorEvaluation.cs` → `SolveIntervalPoint`

本次把世界坐标从快速停止条件中移除，并增加最终曲面偏差检查，确实修复了上轮的大坐标圆柱反例。

但新增条件是：

```csharp
if ((hasDev && curDev <= 1e-11 * geomScale)
    || residual <= ICurveEvaluation.ResidualTolerance
                   * geomScale * geomScale)
{
    converged = true;
    break;
}
```

它允许候选点仅凭很小的曲面偏差停止，没有检查**参数平面近相切时，残差会放大为多大的位置误差**。最终检查也只验证曲面偏差和两个平面残差，没有前向位置误差检查。

### 一个正则单位圆柱反例

取单位圆柱：

\[
x^2+y^2=1,
\]

以及以下内部 Terminator 构造：

```text
B = (1, 0, 0)
E = (-0.9999999999995, 9.999999999998333e-7, 0)

tB = 0
tE = 1
t  = 1e-12
```

E 对应接近半圆终点的位置；两平面按当前 `BuildPlanes` 构造。这里没有参数不可表示或精确节点命中的问题，搜索线在 B 处的斜率约为 `1e-6`，也高于当前拒绝阈值。

当前一阶预测得到：

```text
(1.0, 3.999999999999667e-6, 0)
```

它在**第一次快速检查**中就被接受。独立复算如下：

| 项目 | 数值 |
|---|---:|
| 当前返回位置 Y | `3.999999999999667e-6` |
| 高精度参考位置 Y | `1.561552812808438e-6` |
| 正确位置 X | `0.9999999999987808` |
| 位置误差 | **`2.438447187191534e-6`** |
| 当前曲面几何偏差 | 约 `8.00e-12` |
| 当前目标参数平面残差 | 约 `4.42e-17` |
| 本函数最终长度检查门槛 | 约 `2.00e-7` |
| 返回状态 | **`Success`** |

位置误差约为最终长度检查门槛的 **12.2 倍**，但曲面和两个平面的检查均通过。

参考点是对同一组 binary64 输入、同一条两平面交线，用 100 位精度求解圆柱二次方程，并选择与 B 连接的正向根得到的；不是通过空间最近点近似取得。

**这不是又跳到了另一条连通分支，而是同一局部根尚未求准便提前成功。** 当前上层收到成功后会继续发布、缓存该点，没有再补上位置误差检查。

### 当前已有的数据就能发现问题

候选点处的标量 Newton 修正量为：

\[
\delta\mu
=
-\frac{\phi(x)}
       {\nabla\phi(x)\cdot\ell}.
\]

本例中：

\[
|\delta\mu|
\approx1.7777777778\times10^{-6},
\]

明显大于最终长度门槛。由于 \(\ell\) 是单位向量，这个修正量直接具有空间长度意义。

### 修复意见

将“停止迭代”和“位置可发布”继续分开：

**快速停止可以参考曲面偏差，但发布前至少需要结合搜索方向斜率，检查空间修正量或可靠的根区间宽度。** 当前已有根处 jet，可以复用，不需要再求一次梯度。

对于本例，检查发现修正量过大后继续校正即可。更一般的病态情况，还应考虑残差自身的计算误差；不能只把 `1e-11` 改成更小的固定常数。

规格 §18.2 已明确要求区分小残差与小前向误差，并允许无法满足精度时明确拒绝。

**范围说明：** 这是受 GATE-T 隔离的内部 Terminator 精度问题。本轮没有据此声称公开 PK 入口已返回该错误结果。

## 2. [P2，新回归] 新增的三类几何偏差检查没有计入共享预算

**位置：** 同一函数。

这些调用都没有 `budget.TryConsume(1)`，也没有更新相应求值计数。原有的隐式 jet 求值仍然计费，因此现在是**新增加的检查绕过了原预算边界**。

### 精确线性构造就能复现

```text
所选面：z=0
B=(0,0,0)
E=(1,0,0)
tB=0，tE=1
查询 t=0.5
```

按当前调用链，实际发生：

|---|---|
| B 处隐式 jet | 是 |
| 目标点隐式 jet | 是 |
| 目标候选的几何偏差 | **否** |
| 接受前中点的几何偏差 | **否** |
| 最终几何偏差 | **否** |

独立控制流复算得到：

```text
返回状态：Success
Used：2
实际基础求值入口调用：5
```

这里不包含构造 anchor 时的外部求值，只统计 `SolveIntervalPoint` 内部发生的调用。


若复用已求得的偏差结果，确实省略了基础调用，则不重复扣费；但不能在实际调用仍存在时，只调整报告数字。

## 3. [P2，Oracle 新增检查] 差分样本产生 NaN 时，新的验证仍可通过

**位置：**

`scripts/IcurveEvaluationOracle.cs` → Case F 四分点差分检查

现有 `CaseFValidator` 对原始五项指标的 NaN 防守应保留，那个问题没有重新出现。


没有先检查有限性。尤其 `ourT±h` 是新求值点，其输出不包含在原来的 `CaseFEvalSample` 中。

### 确定的判定器反例

假设 t 处的 D0/D1/D2 和原五项指标都正常，但某次 `D1(t+h)` 出现 NaN：

```text

ourFdErr → NaN
maxOurFdErr → NaN
```

随后：

```csharp
maxOurFdErr > 1e-5
```

为 false，不会抛错；原有 `CaseFValidator` 检查的 t 处指标仍然有限，也不会发现这个差分样本的问题。

**这验证的是 Oracle 防守逻辑的漏洞，不是说你报告的真实 PK 数据里出现了 NaN。** 本轮只做了该判定路径的独立复现，没有运行真实 PK 故障注入。

## 4. 对“Parasolid 省略切向加速度”的结论，应如何处理

**这次增加切向／法向分解和双方 D1 差分，是正确的调查方向。它比之前直接放宽四分点 raw D2 容差更有解释力。**

但要区分三个层次：

**第一，数值观察。** 你报告的法向差约 `3.10e-15`、我方 D2 与 D1 差分差约 `1.86e-11`，支持当前夹具的几何一致性和我方求导实现的数值自洽性。这是有效证据。

**第二，当前脚本实际验证了什么。** 源码计算并判定的是：

\[
\|D_h(\text{ourD1})-\text{ourD2}\|,
\]

同时计算但只记录：

\[
\|D_h(\text{pkD1})-\text{pkD2}\|.
\]

它没有对全部样本汇总、断言：

\[
\|D_h(\text{pkD1})-\text{ourD2}\|,
\]

也没有直接断言：

\[
|T\cdot\text{pkD2}|\approx0.
\]

目前只有首个四分点的明细日志，其余主要是最大误差统计。

因此，“两者 D2 之差几乎纯切向”本身，并不逻辑等价于“PK D2 的切向分量为零”。后一个命题需要直接测量。

**第三，通用接口契约。** 即使上述关系在当前 Case F 的全部样本上成立，也应先写成：

> 在指定 Parasolid build、当前接收得到的 ICurve 夹具和这些查询参数上，观察到返回 D2 的切向行为与数学二阶导数不同。

这还不能证明所有 ICurve、所有构造和所有 build 都采用相同规则。

### 建议补齐的证据

增加上述两个缺失指标，并使用多个不跨 chart 节点的差分步长，检查误差趋势。同时核对同一 t 下 `order=1` 与 `order=2` 请求返回的 D1 是否一致，避免把请求阶数相关的行为混入差分解释。

记录真实 PK build、原始 XT、查询 t、请求阶数及完整精度的输出，而不是只保留六位小数明细。

**单个 \(h=10^{-5}\) 的有限差分不能构成严格数学证明。** 它是很好的数值测试，但仍包含截断和舍入误差，也可能在特殊夹具上出现抵消。

最后，暂时不要为了匹配这个观察而全局删除内核真 D2 的切向分量。内部链式求导需要数学二阶导数；若最终确认某个 PK 接口存在特殊兼容语义，应在明确的兼容层处理，并单列证据和适用范围。
