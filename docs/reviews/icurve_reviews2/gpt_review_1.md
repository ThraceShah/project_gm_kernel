1. [P1，内部 Terminator 路径] 非零 witness 预测仍能落到另一条分支，距离守卫会放行

位置：

Geometry/Intersection/TerminatorEvaluation.cs → SolveIntervalPoint

当前逻辑是：

在 B 处计算一次 μ′
→ 直接外推到目标参数，得到 witnessMu
→ 在目标截面上做 Newton
→ 检查候选点到 B 的距离不超过某个倍数
→ Success

这里没有建立从 \(B\) 到目标根的已验证连接链。距离检查只能排除过远的候选，不能证明候选与 \(B\) 位于同一连通分支。当前源码使用的限制是：

\[
\|x-B\|
\le
4\max\!\left(
\text{chordAdvance},
10^{-4}\max(\text{ChordLength},1)
\right).
\]

它确实比没有检查更严格，但不能支持“彻底杜绝跨分支跳跃”的结论。

一个新的反例：预测值非零，也仍然错误成功

取绕 Z 轴、主半径 \(1.5\)、管半径 \(1\) 的环面。用 \(x=0\) 截它，可以得到两条互不相连的圆：

\[
(y-1.5)^2+z^2=1,\qquad
(y+1.5)^2+z^2=1.
\]

Terminator 构造的 \(B,E\) 都位于 Y 为正的那条圆。定义：

\[
C(\theta)=(0,\;1.5+\cos\theta,\;\sin\theta),
\]

取：

\[
B=C(1.5),\qquad E=C(4.1).
\]

对应的实际输入为：

B = (0, 1.5707372016677028,  0.9974949866040544)
E = (0, 0.9251760534667308, -0.8182771110644103)

tB = 0
tE = 1
t  = 0.55

两个平面按当前 BuildPlanes 和环面在 \(E\) 处的法向构造。这是显式定义的内部一面／两平面制造例，不假设未知的 Parasolid terminator 参数重建规则。

按当前补偿环面残差、预测、八次快速检查以及最终距离守卫复算：

项目	结果

预测点	(0, -2.381649844722773, 1.277777898622656)
最终接受点	(0, -1.5891447176682036, 0.9960186842182511)
原正 Y 分支上的正确点	(0, 0.5298838070471241, 0.2426408295621708)

返回点在 Y 为负的另一条截面圆 上。它足够接近环面、满足两个平面，又落在距离上限内，所以被接受。

这个例子在第八次快速检查时收敛，没有进入未模拟的二分后备。原正 Y 圆弧上的弦投影也没有折叠，其最小切向投影为：

\[
\cos(1.3)\approx0.267499>0.
\]

因此，这既不是非法参数区间，也不是因预测被截断成零而重新触发旧例。新增的一阶外推本身已经跨到了错误分支附近。 环面残差及导数表达式与当前源码一致。

修复意见

不要继续调整距离倍数来逐个拦截例子。应把预测和分支证据分开：

B 处已验证根
→ 有限步长预测
→ 在局部有效邻域内校正
→ 验证后形成新的接受态
→ 推进到目标参数

保存的应是上一接受态的参数、根、局部标量位置及有效域，而不是仅保存由 \(B\) 一次外推到目标的 witnessMu。二分也必须作用在与接受态连接的局部根区间内；无法建立连接时缩步，仍无法区分时明确拒绝。

这与规格 §6.3–6.4 的要求一致：根选择依赖本端 branch witness，并验证端点分支，不能用小残差或最近的标量根替代。

影响范围： 这是内部 Terminator 算法的 P1 错误成功；公开入口仍受 GATE-T 隔离，不应描述成目前公开 PK 路径已经返回该错误点。

2. [P2，数值模块] SVD 的统一缩放修复有效，但仍有两种不同的尺度缺口

位置：

Computation/Numerics/SmallLinearSolve.cs → SvdFactorizeSquare

2.1 Subnormal 输入：确实有问题，但最后是明确失败

对于：

\[
A=10^{-320}I_2,
\]

当前先计算：

var invSMax = 1.0 / sMax;
bWork[i] = a[i] * invSMax;

倒数溢出为 Infinity，工作矩阵随后出现非有限值。但当前代码在恢复奇异值时有有限性检查，因此最终返回 NumericalFailure。本轮完整复算确认了这一点。

这属于“本可处理的良态输入被拒绝”，不等同于把错误解发布为成功。最小修改仍然是：

bWork[i] = a[i] / sMax;

它避免先构造不可表示的倒数。

2.2 混合尺度输入：仅改除法还不够，仍会错误丢失奇异值

取：

\[
A=
\begin{bmatrix}
10^{200}&0\\
0&1
\end{bmatrix},
\qquad \text{rankTolerance}=0.
\]

所有矩阵元素和两个真实奇异值都可以表示。统一缩放后：

\[
B=
\begin{bmatrix}
1&0\\
0&10^{-200}
\end{bmatrix}.
\]

当前仍通过：

sumSq += bkj * bkj;

计算列范数，第二列的平方下溢为零。结果是：

status = Success
sigma  = (1e200, 0)
rank   = 1

对右端 \(b=(10^{200},1)^T\)，随后最小范数求解返回 (1,0)，而不是 (1,1)。这里特意使用零截断阈值，排除“调用方本来就要求将小奇异值截掉”的解释。

本轮复算汇总：

输入	当前结果

\(I_2\)	成功，rank 2
\(10^{-200}I_2\)	成功，rank 2
\(10^{200}I_2\)	成功，rank 2
\(10^{-320}I_2\)	NumericalFailure
\(\operatorname{diag}(1,10^{-200})\)，零截断阈值	成功，但错误返回第二奇异值为零
\(\operatorname{diag}(10^{200},1)\)，零截断阈值	成功，但错误返回第二奇异值为零


因此，上一轮“直接除以 sMax 即可修复”的建议只覆盖倒数溢出，不能作为整个尺度问题的完整修复。

修复意见

保留单边 Jacobi，继续补齐稳定列范数和旋转相关量计算。列范数使用带缩放的平方和或稳定 hypot 累计；旋转阶段的列相关性也应避免未经保护的平方和、乘积溢出／下溢。

如果某个数值范围确实无法可靠处理，可以明确返回数值限制，但不能在调用方未要求截秩时，把丢失的信息当成真实零奇异值成功返回。

这里确认的是 SVD 函数契约问题，没有据此声称已经复现了公开 ICurve 的错误位置。

3. [P2] Terminator 预算仍有漏计与预扣两种问题

位置：

TerminatorEvaluation.SolveIntervalPoint、BracketedSolve

新增 branch jet 漏计：上一轮判断成立

在进入 Newton 之前，代码直接计算：

AnalyticImplicitEvaluation.Evaluate(
    in selectedSurface, in anchor.BranchPoint, 1, out var branchJet)

没有扣预算，也没有增加 evaluations。

用一个精确线性构造即可验证：

所选面：z=0
B=(0,0,0)
E=(1,0,0)
tB=0，tE=1，查询 t=0.5

这个构造的预测点就是目标根。只统计 SolveIntervalPoint 内部的基础求值，不包含外部准备 anchor：

给定预算	当前状态	当前 Used / evaluations	实际隐式求值次数

0	NotConverged	0	1
1	Success	1	2
2	Success	1	2


所以不只是“预算零时偷偷算了一次”：预算为 1 时，会执行两次基础求值并成功。

二分扫描还保留连续预扣

BracketedSolve 每轮先：

budget.TryConsume(2);
evaluations += 2;

然后先求正侧；如果正侧已发现变号区间，立即 break，负侧不再执行。这时两笔费用只对应一次实际求值。

这一处属于保守多扣，不会突破预算，但与前面漏计共同说明：“实际基础求值次数”和“预算计数”仍未完全一致。

修复意见

对 branch jet、正侧扫描和负侧扫描，都采用：

扣一次 → 立即执行这一次求值 → 记录实际调用 → 检查结果

branch jet 求值失败时也应传播失败，或者明确进入具有独立分支验证依据的替代流程，不能静默回到 witnessMu=0。

新增回归不要只测试预算 0。上述预算 1 和 2 的线性构造，能直接区分“包装层计数正常”和“实际成本正确”。
