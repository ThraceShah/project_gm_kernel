## 2. [P1，内部 Terminator] 步长已局部化，但收敛容差仍被世界坐标放大

**位置：** 同一函数中的 Newton 停止条件与最终验证。

当前仍然使用：

```csharp
residual <= ICurveEvaluation.ResidualTolerance
    * Math.Max(1.0,
        Math.Abs(curPoint.X)
        + Math.Abs(curPoint.Y)
        + Math.Abs(curPoint.Z))
```

最终新增的检查只验证两个平面，没有独立检查所选曲面的几何偏差。**这意味着同一个截面仅沿圆柱轴向移动，允许的曲面残差就可能增加多个数量级。** 

### 一个无需环面的简单反例

取单位圆柱：

\[
x^2+y^2=1,
\]

并设置：

```text
B = (1, 0, L)
E = (0, 1, L)

tB = 0
tE = 1
t  = 0.5
```

正确目标点始终是：

\[
(1/\sqrt2,\;1/\sqrt2,\;L).
\]

分别使用 `L=0` 和 `L=10¹³`：

| 项目 | `L=0` | `L=10¹³` |
|---|---:|---:|
| 返回 X、Y | `0.7071067811865476` | **`0.9027923488991147`** |
| 位置误差 | 约 `1.57e-16` | **`0.2767411838197913`** |
| 所选圆柱的几何偏差 | 接近零 | **约 `0.2767411838`** |
| 计算出的隐式残差 | 约 `1.37e-16` | **`0.6300680504615619`** |
| 当前接受结果 | `Success` | **`Success`** |

在后一个输入中，当前残差阈值约为 1，因此 `0.630` 会被接受。两个平面仍然被满足，最终平面检查不能发现错误。

**这不是大坐标导致 X、Y 无法表示所需精度。** Z 是固定的轴向坐标；错误发生在量级约为 1 的 X、Y 上。圆柱的隐式残差和梯度计算本身仍使用局部径向分量。

### 修复意见

应把以下两件事分开：

**求解器是否停止迭代**，可以使用缩放后的残差、步长等指标。

**结果是否可以发布**，必须验证所选面、两个原始平面、目标参数和位置误差要求。

所选面的接受阈值不能依赖世界坐标范数。建议使用统一量纲的几何偏差与局部尺度，并结合完整约束系统的修正量及残差误差判断位置精度。`φ` 对圆柱具有平方长度量纲，对环面又是四次量纲，不能未经缩放便共用同一个世界坐标阈值。

这项不需要重新设计分支算法才能修复，应作为独立的发布条件问题处理。**第 1 项是“精确求到了错误分支”；本项是“根本没有足够贴近所选面”。**

## 3. [P2，新回归] SVD 的 subnormal 列范数往返缩放污染了 U 的单位长度

**位置：** `Computation/Numerics/SmallLinearSolve.cs` → `SvdFactorizeSquare`

这次对原动态范围反例的处理有效。本轮复算确认：

```text
1e-320 I₂
diag(1e200, 1)
diag(1e200, 1e-200)
```

都得到正确的 rank 和对应结果；`diag(1e305,1e-200)` 会明确返回 `NumericalFailure`，没有错误发布 rank。**这些原反例可以关闭。**

但取消小量级输入的全局缩放后，出现了另一个问题。当前先保存：

```csharp
var norm = cj * unitNorm;
colNormB[j] = norm;
```

再通过：

```csharp
var invUnitNorm = 1.0 / (colNormB[j] / cj);
```

恢复无量纲归一化因子。`norm` 若落入 subnormal 范围，已经被粗粒度舍入；再除回 `cj`，不能恢复原来的 `unitNorm`。

### 非对角、条件数为 1 的反例

取：

\[
A=10^{-320}
\begin{bmatrix}
1&1\\
1&-1
\end{bmatrix}.
\]

两列正交、等长，条件数为 1。当前分解返回：

```text
status = Success
rank   = 2
```

但左奇异向量矩阵约为：

\[
U=
\begin{bmatrix}
0.7071977638015374&0.7071977638015374\\
0.7071977638015374&-0.7071977638015374
\end{bmatrix}.
\]

于是：

\[
(U^TU)_{00}-1
=
(U^TU)_{11}-1
\approx 2.5735425179\times10^{-4}.
\]

这不是接近机器精度的正交矩阵。

**这里并没有要求 subnormal 奇异值具有无法达到的高相对精度。** 奇异值本身受到表示间距限制可以理解；但 U 是单位量级的无量纲矩阵，本可准确归一化，不应继承这个中间范数的舍入误差。

### 修复意见

保留每列的无量纲 `unitNorm`，或者在构造 U 时基于 `bWork[:,j] / cj` 重新计算它：

```csharp
u[i * n + j] = (bWork[i * n + j] / cj) / unitNorm;
```

不要通过已经舍入的 `colNormB[j]` 再恢复 `unitNorm`。缓存该量时，排序也必须同步置换。

回归测试应检查满秩输入的 `UᵀU`、`VᵀV`，而不只检查奇异值非零和 rank。对于相等奇异值，U 的具体列可以不唯一，但正交性必须成立。

补充一个术语修正：`diag(1e305,1e-200)` 的两个输入元素和两个奇异值都可表示；受限的是当前归一化表示的动态范围，不是这个矩阵本身超出了 double。当前明确拒绝是可以接受的能力边界，不应解释为输入数值不存在。

## 4. [P2，验收缺口] 四分点 raw D2 门槛放宽五万倍，完整段内验收仍不能关闭

**位置：** `scripts/IcurveEvaluationOracle.cs` → Case F。

`CaseFValidator` 本身这次修得正确：它拒绝空样本、非法容差，以及非有限、负数和超限指标。测试也直接复用了这个判定器。**上轮 NaN 绕过的问题可以关闭。** 

但 Oracle 调用它时，对两组内部样本采用了不同的 raw D2 门槛：

```csharp

    midpointSamples, 1e-8, 1e-6, 1e-6, 1e-5, 1e-8, ...);

// 1/4、3/4 点
CaseFValidator.Validate(
    quarterSamples, 1e-8, 1e-6, 0.05, 1e-5, 1e-8, ...);
```

**四分点的 raw D2 容差比中点大了 50,000 倍。** 当前差异不仅是采样位置变化，也改变了验收精度。

### 当前 PASS 能证明什么

例如一个样本的其他误差均为零，只有：

```text
DiffRawD2 = 0.01
```

它会被中点策略拒绝，却被四分点策略接受。切向加速度扰动可以保持曲率和主法向不变，因此其他指标不足以补上这个缺口。

这不是 `CaseFValidator` 的实现错误——它正确执行了调用方传入的 `0.05`。**问题在验收策略和完整原生 D2 兼容声明之间。**

当前日志中的 `max|ΔD2_raw_mid|` 已明确限定中点，这一点是诚实的；但它不能证明新增 96 个四分点的 raw D2 也达到机器精度。四分点的 `geomD2`、`circleDelta` 也没有累入对应的 `maxD2`、`maxCircle`，所以这两个日志最大值仍主要反映中点，而不是全部 144 个样本。

### 修复意见

首先记录四分点真实的：

```text
t、所在原始段、双方 D0/D1/D2、
ΔD2 的切向分量和法向分量、实际采用的容差
```

目前提供的日志不足以判断非中点差异来自我方求导、PK 接口语义，还是其他参数对应问题，不能预先认定它是无害的切向差异。

随后，在同一原始段内部，用多个差分步长分别核对双方的：

\[
\frac{D1(t+h)-D1(t-h)}{2h}
\quad\text{与}\quad D2(t).
\]

差分点不得跨节点。这样才能区分“返回的 D2 是否是各自 D1 的导数”和“两者是否采用相同接口语义”。

在差异原因确认之前，应分别记录“中点 raw D2 通过”和“四分点 raw D2 尚未通过统一精度验收”。若确实需要不同阈值，必须有独立的误差或兼容性依据，不能只因为该阈值使测试通过。规格 §21.6–21.7 对参数保真及容差证据有明确要求。
