# B 曲线与解析面：完整有界求交

`PK_SURF_intersect_curve` 现对球、圆柱、圆锥和普通环面接通普通及正权重有理 B 曲线。生产求交完全在自研内核内执行；真实 Parasolid 只作为独立验证输入。

## 算法与范围

| 支持面 | B 曲线最高次数 | 每个跨度的隐式多项式最高次数 |
| --- | --- | --- |
| 平面 | 16 | 16，沿用既有路径 |
| 球、圆柱、圆锥 | 8 | 16 |
| 普通环面，主半径大于次半径 | 4 | 16 |

每个非空节点跨度都先与请求的曲线参数区间相交。多项式 de Boor 插值把该段的四个齐次坐标转换为完整多项式；球、柱、锥代入二次隐式方程，环面代入四次隐式方程。正权重保证有限有理曲线与分子多项式有相同的零点。

曲线坐标在形成二次或四次乘积**之前**映射到局部 `[-1,1]` 参数，并用二进制幂缩放位置与权重。这个顺序减少高次多项式中心平移中的系数抵消；二进制幂缩放避免任意除数把精确切触扰动成两个根。局部中心通过相对节点的差计算，返回参数通过区间起点加相对偏移恢复，避免 `[2^53,2^53+2]` 这类参数跨度因绝对中点舍入而漏掉末端根。

沿用 `BoundedPolynomialRoots` 的递归导数隔离：先隔离所有临界点，再在相邻临界点之间的单调区间求根，并逐一检查重根。算法不依赖有限参数采样、初始猜测或只追踪一条分支。临界值的舍入误差不能区分切触与相邻根对时，返回数值失败。

每个候选结果重新计算原 B 曲线位置与切向，以及解析面的几何距离和法向；只有支持面残差通过后才发布参数、UV 和 simple/tangent 分类。圆锥的远半部候选会被剔除。原生 trimmed curve 的参数回映沿用统一入口。

## 重合区间

完整重合跨度合并成连通的参数区间，输出 start/end 两个边界标记，并使用原生 UV 哨兵 `(-1,-1)`。球、柱的近重合判定使用齐次多项式的全区间绝对和界、正权重下界以及浮点运算余量，不用几个位置采样代替整段判断。圆锥重合还须证明 generator 在区间内不经过零，并按其符号排除远半部；无法与顶点隔离的奇异重合请求返回数值失败。真实 PK 对穿过顶点的重合 generator 也返回 `PK_ERROR_cant_do_intersect`，负向协议单独核对。

这些是有明确上限和几何残差门槛的浮点算法，不是任意精度代数证明。次数超界、非正权重、非普通环面、超出 B 曲线保存的基本参数域、无法区分的临界值、几何奇异点和计算范围失败都返回明确错误。平方下溢不能将原本不重合的曲线误判成零多项式；例如极大轴向坐标与微小径向尺度组合无法安全处理时会失败。

## 验证入口

`tests/KernelTests/BCurveAnalyticIntersectionTests.cs` 验证完整多根、普通/有理曲线、切触、所有节点跨度、跨度端点去重、局部参数区间、重合标记合并、锥远半部、trim 参数、次数边界、极端尺度失败、返回缓冲区故障回滚及热路径零托管分配。

`scripts/BCurveAnalyticIntersectionOracle.cs` 用同一几何定义与 API 参数分别调用自研内核和真实 Parasolid，要求结果数量、位置、曲线参数、UV、分类一致。随后用两条路径各自算出的交点参数分割各自的曲线，将每个非空区间独立制成 wire。自研 wire 写出文本 XT 后，由真实 PK 接收；两份独立 wire 都执行完整 `PK_BODY_check`，并比较拓扑数量、类型、sense、容差、missing 和严格结构差异。API 返回的是交点数组，这些线框验证交点对曲线后续分段建模的实际作用。

验证还包含不均匀节点的 C1 普通／有理二次曲线，以及原曲线含 C0 角点的情况。求交仍一次请求完整参数域；用于逐段线框的划分同时包含交点和原始角点参数。独立用例另外直接请求完整 C0 曲线的 legacy 和 `_2` wire API，要求自动分成三条边、每条边支持曲线精确裁剪并保留参数域、返回的 indices 全部指向同一输入曲线。几何 G1 连续但参数速度突变的一次和二次曲线必须保持一条边，不能只按内部节点重数盲目分割。

原生 SDK 自身的验证边界单独保留：普通三次曲线往返穿过环面、线性横向分离为 `0.01*t` 时，两条求交路径都得到完整的 12 个根，但真实 PK 直接生成的首段 wire 在完整体检查中报告 `PK_EDGE_state_bad_vertex_c`。该用例记录原始根集与两边 wire 的检查结果，不计入有效线框正向验收。正向 12 根用例把横向分离扩大为 `0.125*t`，仍保留 12 个独立根和 13 个线框区间，所有区间都必须通过完整体检查及严格结构比较。

```sh
MSBUILDDISABLENODEREUSE=1 dotnet run --no-cache scripts/BCurveAnalyticIntersectionOracle.cs -p:UseSharedCompilation=false -p:BuildInParallel=false
```

运行报告与逐段 XT 位于 `temp_docs/bcurve-analytic-intersection-oracle/`。与其他 oracle 并行执行时，应由主构建先更新生产 DLL，再使用 `-p:BuildProjectReferences=false`，避免共享输出目录的编译竞争。

本次独立验收包含 31 个主场景：30 个求交或线框正向场景，以及 1 个圆锥顶点奇异重合的失败协议对照；另保留 1 个上文所述原生 wire 检查边界。普通三次曲线／环面的 12 根、非均匀 C1 多跨度、C0 自动分边、G1 速度变化保留单边，都进入了完整体检查和严格比较门槛。

本扩展并不包含任意 NURBS/NURBS 曲面求交或一般 NURBS 实体布尔。
