# 共轴圆柱实体的连续布尔与轴向切割

本模块扩展阶段 C 的解析 B-rep 闭环。输入从当前实体的支持面、完整圆边、fin 和材料侧读取，不依赖创建历史。计算始终在自研内核中进行；真实 Parasolid 仅用于独立验证。

## 公开范围

`PK_BODY_boolean` / `PK_BODY_boolean_2` 支持共轴、仅含圆柱面和垂直轴平面的规则实体的并、交、差。每个圆柱 face 是两个完整圆环之间的带，每个平面 face 是圆盘或同心圆环。支持实心柱、通孔、封闭圆柱空腔、阶梯轴和这些实体的连续布尔结果，包括任意共同空间轴方向及反向参数轴。

多工具的相交和相减使用工具材料的并集。输出可以包含多个断开的实体；空结果消耗输入。相交、相切端盖、重合支持面和完全分离情况有独立的状态与身份验证。默认保留 imprint 分段，例如同半径部分重叠圆柱的并集保留三段圆柱 face；`merge_imprinted` 开启时合并连续相同支持面。

`PK_BODY_section_with_surf` 支持垂直共同轴的任意放置平面，以及 front、back、both 三个 fence。切穿实心体、通孔和封闭空腔均构造真实封盖。返回的 face 数组只包含新产生的切割封盖，不包含原来已经在该平面上的 face。无交集的切割按所选侧保留或删除原体。

切割面可以直接取自输入 body 的支持面。内核在修改之前保存其定义并暂时替换输入中的支持，避免布尔步骤先删除随后还需要的几何。操作结束时，原支持面的材料边界仍有存续部分时恢复其身份；原边界被全部消耗时按原生行为删除原 surface。不能把所有传入工具面都视作永久 orphan。已有几何依赖引用的 body-owned 工具面暂不进入该保护路径，显式返回未实现。

操作后查询被消费实体的 `PK_ENTITY_ask_class` 返回 `PK_ERROR_not_a_tag`（22），存续实体返回 0。独立切割 oracle 同时比较 source body 和工具 surface 的实际查询错误码，覆盖生命周期状态及其公开查询合同。

`PK_BODY_contains_vector` 支持上述原生或导入模型。边界优先返回 edge，然后返回 face；体内部返回材料 region，封闭空腔返回自己的 void region，外部返回无界 void region。

## 算法与完整性

每个圆柱 face 在径向—轴向平面中对应一条竖直线段，每个平面 face 对应水平线段。所有半径和轴向端点形成精确区间 arrangement。径向有向穿越数确定各区间的输入材料，所有水平面的法向与材料跳变逐项核对。对每个完整区间执行布尔逻辑，因此不靠采样网格寻找遗漏的分支。

输出材料的四邻接连通分量确定结果 body。针对每个材料分量重新连通外部空白区域，区分外壳、封闭空腔和不同 body 的外部区域。输出边界合并为圆柱带与圆盘/环面，直接构造解析面、完整圆边和 fin incidence。没有使用显示三角网格。

这里的平面区间中点仅用于已经由完整几何断点分割后的恒定材料分类；它不是曲面求交的分支发现手段。

## 几何与容量边界

读取器最多接收 128 个 face、257 个径向或轴向断点；输出临时边界最多 1024 个 face 和圆边。超界返回显式错误。

空间共轴与重合判断使用 `1e-9` 的受支持几何精度。轴平行性使用叉积范数，要求角度误差处于浮点舍入量级（不超过 `8e-15`），并乘以模型半径或相对高度后不超过空间阈值的八分之一。不能仅用接近 1 的点积判断共轴：薄而宽的轻微倾斜圆柱会被错误地旋正。对应负向回归使用半径 20、高度 0.01、轴倾斜 `1e-8` 的两个有效柱体，明确拒绝且保留输入。

不支持非共轴圆柱、圆锥/球/自由曲面的混合输入、非完整圆边、带 seam 顶点的分片圆柱、仅有 fin 参数曲线的容差边，以及旋转后形成非流形圆接触的棋盘式材料交会。轴向 section 不接受斜切平面。现有平面和完整球体的其他建模路径保持各自支持范围。

## 实体身份、tracking 与原子性

Union 的每个连通分量以最早参与的输入 body 作为存续 body。完全独立的工具体直接保留原 body、face、edge；与其他工具相交的工具分量也独立处理。相交和相减有结果时保留 target body。源 face 的首个存续结果保留其句柄；保持两个源支持面的既有圆边保留其句柄。新的 imprint 圆边使用新实体。

Tracking 返回真实来源关系：每个新交圆关联相关输入的 face 或既有 edge，保留来源类别和多重性。它不是仅按最终面数合成的摘要。返回数组按已有 `PK_MEMORY_free` / `_r_f` 协议释放。

构造、面/边句柄迁移、结果替换及工具消耗均包含在 command transaction 内。分配失败释放尚未发布的返回缓冲区，并恢复原始 B-rep。两个切割侧产生的 body 和 face 数组也有故障注入回归。

## 独立验证

运行 `scripts/RotationalModelingOracle.cs`。每个场景分别用本项目 API 和真实 PK API 创建输入、执行相同操作；本项目结果以 text XT 导出，再由真实 PK 接收。验证包括：

- 调用状态、结果数、原 body 存活及输出 body 与输入 body 的对应关系。
- Tracking 的来源几何、来源类别、记录多重性和产品圆边。
- 默认完整 `PK_BODY_check`、region/shell/face/edge/vertex 数量。
- 保持开启的类型、sense、容差、missing 和 topology `PK_DEBUG_BODY_compare` 检查。
- 体积、面积、质心、惯性等 15 项质量属性。
- 自研输出和独立原生 XT 导入结果的点分类与边界维数。
- 原生 XT 导入 → 复制 → 删除原体 → 平移副本 → 再次布尔的生命周期。

日志与每个生产者的 XT 保存在 `temp_docs/rotational-modeling-oracle/`。实际通过数量以该次运行的报告和阶段验证记录为准。

本轮独立运行通过 96 个场景：57 个布尔场景和 39 个轴向切割场景。切割矩阵包括 6 个输入 body 自带工具面的消费/保留对照，以及 6 个一般空间轴与反向切割面方向的对照；全部使用原始结果的严格 sense 检查，没有用规范化副本放行。

```sh
MSBUILDDISABLENODEREUSE=1 dotnet run --no-cache scripts/RotationalModelingOracle.cs -p:UseSharedCompilation=false -p:BuildInParallel=false
```

统一构建已更新生产程序集时，可加 `-p:BuildProjectReferences=false`。本模块没有新增替代版本的公共 API，继续沿用已有 Boolean、section 和 contains 入口。
